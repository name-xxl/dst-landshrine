## 2. Mod 基础结构

Mod 文件夹放在（联机版）：
```
Documents\Klei\DoNotStarveTogether\mods\<你的mod名>\     -- 本地测试
Steam\steamapps\common\Don't Starve Together\mods\       -- 也可以，随订阅的 mod 一起
```

最小结构（Hello World 只需要两个文件）：
```
my-mod/
├── modinfo.lua      ← 必需。元信息：名字、版本、配置项
├── modmain.lua      ← 必需。代码入口，游戏加载 mod 时执行
├── modicon.tex/xml  ← 可选。mod 列表图标
├── scripts/         ← 可选。自定义代码（require 按此路径查找）
│   ├── components/  ← 自定义组件
│   ├── prefabs/     ← 自定义预制体（通过 PrefabFiles = {...} 声明）
│   ├── screens/     ← UI 界面
│   └── widgets/     ← UI 控件
├── images/          ← 图集 .xml + 贴图 .tex
├── anim/            ← 动画 .zip（由动画编译器生成）
└── exported/        ← Spriter 动画工程（发布时可删）
```

### modmain.lua 执行环境

- **modmain 运行在一个受限环境**：看不到游戏全局变量，要访问游戏全局需要 `GLOBAL` 前缀。
- `require` 被重定向，可直接 require `scripts/` 下的游戏脚本和自己 mod 的脚本（mod 自身路径优先）。
- 常用环境变量/函数（由 mod 系统注入）：`GLOBAL`、`require`、`GetModConfigData`、`AddPrefabPostInit` 等所有 Add* 函数、`PrefabFiles`、`Assets`、`modname`。
- **客户端/服务端都执行** modmain；要区分场景用：
  ```lua
  if GLOBAL.TheWorld ~= nil and GLOBAL.TheWorld.ismastersim then  -- 服务端逻辑（一般在 prefab postinit 里判断）
  if GLOBAL.TheNet:GetIsClient() then  -- 纯客户端
  ```
- `client_only_mod = true` 的 mod 只在客户端执行（如 Combined Status）；`all_clients_require_mod = true` 的 mod 是服务端 mod，客户端也必须装（如木牌传送）。

### 最小 modinfo.lua 模板

```lua
name = "我的Mod"
author = "我"
version = "1.0.0"
description = "做什么的"
api_version = 10              -- 联机版固定 10
dst_compatible = true
client_only_mod = true        -- 纯客户端改 UI 的设 true
all_clients_require_mod = false
server_filter_tags = {}
icon_atlas = "modicon.xml"
icon = "modicon.tex"

configuration_options = {     -- 配置项（mod 设置界面）
    {
        name = "MY_OPTION",
        label = "选项名",
        hover = "鼠标悬停说明",
        options = {
            {description = "开", data = true},
            {description = "关", data = false},
        },
        default = true,
    },
}
```

modmain 里读取：`local opt = GetModConfigData("MY_OPTION")`

## 3. modinfo.lua 速查

| 字段 | 说明 |
|---|---|
| `name` / `author` / `version` / `description` | 基本信息	description 里 `\n` 可换行 |
| `api_version = 10` | DST 必填；单机饥荒用 6（`api_version_dst` 区分双版本 mod） |
| `dst_compatible` | 是否兼容联机版 |
| `dont_starve_compatible` / `reign_of_giants_compatible` / `shipwrecked_compatible` / `hamlet_compatible` | 单机版及 DLC 兼容标记 |
| `client_only_mod = true` | 纯客户端 mod，不标记服务器为 modded，进任何服都能用 |
| `all_clients_require_mod = true` | 服务端 mod，所有进服玩家必须订阅 |
| `server_only_mod = true` | 只有服务器需要装 |
| `server_filter_tags` | 服务器搜索标签 |
| `priority` | 加载顺序，数值越大越先加载（依赖其他 mod 的要更先） |
| `icon_atlas` / `icon` | mod 图标 |
| `forumthread` | 论坛帖子链接 |
| `configuration_options` | 配置项数组，见上节模板 |

## 4. modmain 常用 API 速查（Add* 全家桶）

> 官方没有正式 API 文档，权威来源是游戏自带脚本 `modutil.lua`（所有 Add* 定义都在里面）。
> 游戏脚本位置：`steamapps\common\Don't Starve Together\data\databundles\scripts.zip`（解压只读即可）。

### 注入/挂钩类（改官方行为的核心手段）

| API | 用途 | 本地示例 |
|---|---|---|
| `AddPrefabPostInit(prefab, fn)` | 官方/任意 prefab 创建后追加修改 | 木牌传送给 homesign 加组件（modmain.lua:35） |
| `AddPrefabPostInitAny(fn)` | 所有 prefab 都回调 | — |
| `AddComponentPostInit(component, fn)` | 组件类构造后修改 | Combined Status 挂 kramped（modmain.lua:547） |
| `AddClassPostConstruct(classfile, fn)` | **改 UI/任何 Class 的主手段**：脚本文件里 Class 构造后回调 | Combined Status 改 badge/uiclock/statusdisplays 全用它 |
| `AddGamePostInit(fn)` / `AddSimPostInit(fn)` | 游戏/世界初始化后回调 | — |
| `AddPlayerPostInit(fn)` | 玩家生成后回调 | — |

```lua
-- 例：给官方控件加东西（Combined Status 的核心手法）
AddClassPostConstruct("widgets/badge", function(self)
    local _SetPercent = self.SetPercent
    function self:SetPercent(val, max, ...)
        _SetPercent(self, val, max, ...)
        -- 自己的逻辑
    end
end)
```

**Hook 惯用写法**（保存旧函数 → 包装 → 调旧函数，链式兼容其他 mod）：
```lua
local _OldFn = self.SomeFn
function self:SomeFn(...)
    _OldFn(self, ...)          -- 先调原逻辑（或按需要后调）
    return --自己的逻辑
end
```

### 新增内容类

| API | 用途 |
|---|---|
| `AddRecipe(name, ingredients, tech, config)` | 新配方（旧 API；新版游戏推荐 `AddRecipe2`，见 modutil.lua 实际签名） |
| `AddRecipe2(name, ingredients, tech, config, filters)` | 新版配方 API（2023+ 游戏版本） |
| `AddRecipeFilter(fn)` / `RemoveRecipe(name)` | 改/删官方配方 |
| `AddCharacter(name)` | 注册自定义角色（配合 `Prefabs/characters/` 结构） |
| `AddMinimapAtlas(atlas)` | 小地图图集 |
| `AddLevelPreInitAny(fn)` / `AddLevelPreInit(level, fn)` | 改世界生成配置 |
| `AddTaskPreInit(task, fn)` / `AddRoomPreInit(room, fn)` | 改世界生成的任务/房间 |
| `AddLevelPreInitAny` 里改 `map_gen` 等可控制地形 |

### 交互类（右键动作）

| API | 用途 | 本地示例 |
|---|---|---|
| `AddAction(name, str, fn)` | 注册新动作 | `DESTINATION_UI`（木牌传送 modmain.lua:76） |
| `AddComponentAction(type, component, fn)` | 何时显示该动作：type ∈ `SCENE`（对场景实体右键）/ `USEITEM`（物品用在实体）/ `POINT`（用在地点）/ `EQUIPPED` | 木牌传送 modmain.lua:89 |
| `AddStategraphActionHandler(sg, handler)` | 动作触发的状态图状态 | 木牌传送 modmain.lua:101（`"wilson"` 服务端 + `"wilson_client"` 客户端都要加） |
| `AddStategraphEvent/State/PostInit(sg, ...)` | 改状态图 | — |

```lua
-- 完整右键动作三件套（摘自木牌传送）
AddAction("DESTINATION_UI", "右键选择目的地", function(act)
    -- act.doer 玩家 / act.target 目标 / act.invobject 物品
    act.target.components.travelable:BeginTravel(act.doer)
    return true
end)
GLOBAL.ACTIONS.DESTINATION_UI.priority = 1

AddComponentAction("SCENE", "travelable", function(inst, doer, actions, right)
    if right then table.insert(actions, GLOBAL.ACTIONS.DESTINATION_UI) end
end)

AddStategraphActionHandler("wilson", GLOBAL.ActionHandler(GLOBAL.ACTIONS.DESTINATION_UI, "give"))
AddStategraphActionHandler("wilson_client", GLOBAL.ActionHandler(GLOBAL.ACTIONS.DESTINATION_UI, "give"))
```

### 网络 RPC（客户端→服务端）

```lua
-- 服务端（modmain.lua）
AddModRPCHandler("MyMod", "DoThing", function(player, arg1, arg2) ... end)

-- 客户端发起
SendModRPCToServer(MOD_RPC["MyMod"]["DoThing"], arg1, arg2)
```
> RPC 参数只支持基础类型/实体引用；复杂表格要自己序列化（木牌传送的 travelscreen 就是拼成字符串再发 index）。

### 全局访问要点

- 游戏全局用 `GLOBAL.xxx`：`GLOBAL.TheWorld`、`GLOBAL.TheNet`、`GLOBAL.TUNING`、`GLOBAL.STRINGS`、`GLOBAL.require`
- `TUNING` 可以放共享数据给其他脚本/mod 用（Combined Status 把温度单位函数放 `TUNING.COMBINED_STATUS_UNITS` 暴露给别的 mod）
- 检测其他 mod 是否启用：`GLOBAL.KnownModIndex:IsModEnabled("workshop-xxxxx")`

## 5. 事件与监听

```lua
-- 监听实体事件（第三个参数可选指定监听对象，强烈建议带上防泄漏）
inst:ListenForEvent("healthdelta", function(inst, data) end, player)

-- 监听世界状态（DST 标准做法，字段变化时触发）
inst:WatchWorldState("season", function(inst, season) end)
inst:WatchWorldState("cycles", function(inst, cycles) end, GLOBAL.TheWorld)

-- 推送/触发事件
inst:PushEvent("myevent", {key = value})

-- 定时
inst:DoTaskInTime(3, function() end)      -- 一次性（实体侧）
inst:DoPeriodicTask(1, function() end)    -- 周期
```

常用事件：`healthdelta` `hungerdelta` `sanitydelta` `temperaturedelta` `ms_closepopups`、世界事件 `cycleschanged` `seasonlengthschanged` `moonphasedirty`、战斗 `attacked` `death`。
完整清单查游戏脚本：`components/` 下各组件源码里的 `PushEvent` 调用就是事件文档。

## 6. 网络同步：replica / classified / RPC

DST 是 C/S 架构，**客户端没有服务端组件**。让客户端看到服务端数据的三层结构（木牌传送是完整范例）：

1. **组件本体**（服务端）：`scripts/components/travelable.lua` —— 真实数据和逻辑
2. **replica**（两端）：`scripts/components/travelable_replica.lua` —— 客户端读数据的镜像。注意 `AddReplicableComponent("travelable")` 注册，且客户端 prefab 里 `SetPristine` 之前就要 `AddTag("_travelable")` + 客户端装 replica（看 `travelable_classified.lua` 和 modmain 的 tag 操作）
3. **classified**（隐形网络实体）：`scripts/prefabs/travelable_classified.lua` —— 用 `net_string`/`net_byte` 等 netvar 承载数据，自动同步给客户端，客户端监听 netvar 的 dirty 事件更新 UI

数据流：服务端组件改数据 → 写 classified netvar → 引擎自动同步 → 客户端 replica 监听 dirty → 更新 widget。
常用 netvar：`net_bool` `net_byte` `net_shortint` `net_string` `net_entity` `net_event`。

## 7. 调试方法

### 控制台（` 键打开；宿主/管理员可用）

```lua
c_spawn("log", 10)            -- 刷实体/物品
c_give("log", 10)             -- 直接进背包
c_sel()                       -- 选中检查的实体 → c_sel().components...
c_goto()                      -- 传送到选中实体
c_kill(), c_godmode(), c_speed(10)
TheWorld:PushEvent("ms_nextcycle")  -- 跳天
c_findnext("pigman")          -- 找实体
```
远程服务器调试：控制台左侧切换「远程」。

### 日志与报错

- 日志文件：`Documents\Klei\DoNotStarveTogether\client_log.txt`
- mod 报错会在 mod 菜单和日志里显示堆栈；`modmain` 里 `print()` 输出到该日志
- 游戏更新后 mod 崩溃：先看 `modutil.lua`/对应官方脚本有没有改签名（对照 `scripts.zip`）

### 调试渲染

调试键（需在菜单里开）：Backspace 显示实体调试信息、F9/F10 部分调试 UI；`TheDebugDraw`？以当版本为准。

## 9. 学习路径建议

1. **Lua 基础**（1-2 天）：重点是 table、metatable、`Class()` 机制、闭包——饥荒脚本的 `Class`、`Class(..., nil, {field = onsetter})` 属性回调写法要能看懂。
2. **读懂游戏脚本结构**：解压 `scripts.zip` 只读不改；重点翻 `modutil.lua`（API 定义）、`prefabs/`、`components/`、`widgets/`。
3. **从改 UI 入门**：仿 Combined Status 用 `AddClassPostConstruct` 包装官方 widget（不用碰美术就能出效果）。
4. **做新物品/组件**：仿木牌传送 —— prefab + component + replica + action 四件套。
5. **需要美术再学 anim 流程**（Spriter + autocompiler），前期用现成 anim/贴图。
6. **进阶**：世界生成（task/room）、状态图、大脑（behaviortree）、RPC/netvar、多 mod 兼容（priority、检测 KnownModIndex）。
